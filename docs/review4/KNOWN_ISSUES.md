# ArogyaAI — Known Issues

## Issue 1: Pydantic V2 @validator Deprecation

**Description:** `backend/schemas/prediction.py` uses Pydantic V1-style `@validator` decorators, which are deprecated in Pydantic V2.

**Severity:** LOW

**Affected Feature:** Input validation for /api/predict

**Reproduction:** Run `venv\Scripts\python.exe -m pytest tests/` — warnings appear in output.

**Root Cause:** The validators were written for Pydantic V1 syntax and not yet migrated to V2 `@field_validator` style.

**Current Status:** Non-breaking. Validators function correctly. Pydantic V2 still supports V1 syntax with a deprecation warning.

**Effect on Demo:** None. The warning only appears in test output, not in the running application.

**Workaround:** Ignore the warning during the demo.

**Resolution Required:** Migrate to `@field_validator` post-review.

## Issue 2: Firebase Live Credentials Required for Full UI Demo

**Description:** The frontend's authenticated flows (login, patient management, diagnosis saving, admin panel) require a live Firebase project with provisioned accounts.

**Severity:** MEDIUM

**Affected Feature:** All authenticated UI workflows

**Reproduction:** Start frontend without any Firebase accounts in the project → login page shows but credentials are unavailable.

**Root Cause:** Firebase Auth is an external cloud service. The project uses the real Firebase project `arogyaai-cloud-ad667`. Accounts must be created manually.

**Current Status:** Blocked on external service provisioning.

**Effect on Demo:** Demo cannot be run without at least one approved doctor account.

**Workaround:**
- Use the local Firebase emulator: set `VITE_USE_FIREBASE_EMULATORS=true` in `frontend/.env.local` and start the emulator with `firebase emulators:start`.
- Or use a real account already in the live project.

**Resolution Required:** Prepare the demo account before the presentation.

## Issue 3: Gemini API Key Required for Full Recommendation Output

**Description:** The Ayurvedic recommendation section in the prediction response is generated by the Gemini LLM. Without a valid API key, a static fallback message is shown.

**Severity:** MEDIUM

**Affected Feature:** Ayurvedic recommendation in /api/predict response and DiagnosePage result

**Reproduction:** Start backend without `GEMINI_API_KEY` set in .env → prediction succeeds but recommendation shows "AI Ayurvedic explanation is temporarily unavailable."

**Root Cause:** The Gemini API requires an API key. The key is intentionally not committed.

**Current Status:** Designed fallback in place. The prediction pipeline is fully functional without the key.

**Effect on Demo:** Minor — narrate the fallback as a designed safety feature. Or add the key to .env before the demo.

**Workaround:** Set `GEMINI_API_KEY` in `.env` from https://aistudio.google.com/apikey.

**Resolution Required:** Your action: add the key before the demo.

## Issue 4: NumPy 2.5 Array Shape Deprecation in joblib

**Description:** When loading the model artifact, joblib internally uses an assignment to `array.shape` that is deprecated in NumPy 2.5.

**Severity:** LOW

**Affected Feature:** Model loading at startup

**Reproduction:** Any test run or backend startup shows the warning.

**Root Cause:** Internal to joblib v1.3. Not our code.

**Current Status:** Non-breaking. Model loads correctly.

**Effect on Demo:** None. Warning only visible in terminal output.

**Workaround:** Ignore. Will be fixed in a future joblib release.

**Resolution Required:** None before demo. Retrain with a newer joblib when available.
